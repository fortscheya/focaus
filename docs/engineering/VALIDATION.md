# 验证与验收计划

工程契约 2.0.0｜2026-10-18。此文是未来执行方案，本轮未创建测试程序、解码音频、调用模型或运行产品。当前已确认要求不能降低；未定数值先测基线，再由用户与总控共同锁定。

## 1. 验收证据与固定要求

验证分四层：契约静态检查→模块内验证→真实模块集成→真实课程实时回放及课后处理。模拟前端、脱敏fixture、模型格式返回可支持前两层，不能冒充后两层。每个结果记录代码commit、契约/格式/模型/提示版本、输入资源hash、处理参数、运行模式、机器/系统必要信息、事件与时间指标、人工校对版本及失败样例；不记录凭据、私有URL或整段敏感日志。

| 已确认要求 | 判定方式 | 不允许的替代 |
| --- | --- | --- |
| focaus完整结果≤15秒 | 从按钮/快捷键输入到全部正文校验完成并可见，逐次计时 | 首字/占位卡片、仅服务latency、把P95达标冒充每次达标 |
| 进度约10秒更新 | 记录有新证据时调度、完成和显示间隔及ASR滞后 | 旧每分钟定位或按时间自动加页 |
| 证据落后超过30秒待更新 | 依据所用音频截止而非返回时间，检查30秒边界两侧 | 返回新响应就刷新“最新”标签 |
| 原声独立与原始定稿不覆盖 | 注入网络/模型/解析故障，核查原声与stable raw hash | API不报错/短demo录到就称可靠 |
| 关键含义、用户编辑、删除意图保护 | 有针对性的逐项人工与结构检查 | 只看整篇通顺或平均字错率 |
| 原生可编辑对象与引用可追 | 操作实际单元格/系列/节点、往返保存、来源导航 | 截图相似、文字抽取成功 |
| 自动原生2D/3D知识组件 | 从知识识别到插入、实际调参/单步、确定性数学检查与恢复 | 静态截图、外链、模型口头判断数学正确 |
| 课件/笔记/两层转写全文与Command+F | 未挂载范围、精确定位、覆盖/版本/删除、真多窗焦点 | 浏览器find或只搜索可见DOM |
| focaus理解衔接 | 当前问题、讲授关系、必要前提、自适应取舍均有证据并在15秒内完整呈现 | 只改名称/输出页码/平均压缩历史/首段先出 |

任何固定要求失败都记录失败，不将异常响应或“部分依据”计成完整成功。服务故障可展示产品降级能力，但性能报告须单列失败/超时，不排除后声称达标。“约10秒”的可接受波动、各类质量比例及资源上限尚未定量，由基线数据共同确定；不能据此把30秒陈旧规则或15秒完成要求变成可随意调整的参数。

## 3. 两条真实课程验收线路

### 3.1 实时1倍速回放

以原始时间顺序1倍速馈送选定音轨到与真实采集相同的音频支路，测试时钟隔离未来内容。实际麦克风长录音另测，文件馈送不能替代设备/权限/关窗验证。

在预先固定触发点记录：ASR首个有效文本与final延迟、修订幅度、实时coverage、进度输入截止/候选/定位、catchup触发和完整显示、生成/编辑冲突。只能读取此刻已进入管线的音频与当时可用的资料版本；预先有课件可以读，未来转写和课后生成笔记不许泄漏到实时快照。

插入断网→继续录音→联网：先验证恢复到当前streaming，再看filetrans按历史时间补洞、不重复、不覆盖稳定实时。加入暂停/回放/继续、跨窗转移、删资料、用户输入、深转换竞争、限流和云超时。标出天然样本缺口与人工注入故障，分别统计。

### 3.2 课后完整处理

同一原件另建隔离验证库，通过filetrans处理全部已确认范围，检查长任务/分片/边界/说话人标记/时间映射，再做二次转写、笔记五档、资料对象、问答和完整课堂包恢复。保前一实时运行数据以比对，不把课后答案回灌为实时已知事实。

比较实时与课后差异时以同一人工真值/原始区间为基准，报告新增覆盖、不同错误与整理变更，不能默认filetrans必然更准。非实时全量评测运行可生成对照结果，但产品补洞路径仍不得改写stable实时底稿。

### 9.1 V18–V21：交互组件

准备一段适合参数探索的2D函数/变量关系笔记、一段有明确定义的卷积课堂片段及相关页、无可视化价值的事实列表；另准备真实定义缺失/重定义、同概念不同目的的反例。人工先标哪些知识值得可视化及课堂参数/演示数据，不能以模型自己选择结果作为标准答案。

1. 走完整自动链，确认两种组件确实插入原生对象图；重复相同输入/仅语言变动/相同来源版本重试不重复，负例不机械生成。记录误触发/漏识别/无模板/失败，质量比例先测基线。
2. 使用DATA §11.3数学fixture：手算cross-correlation的−4与convolution的+4、stride/padding输出形状；另准备非方阵/非对称padding、多通道/含bias、非法零stride/负padding/核尺寸变更/超资源输入。独立参考计算核对每格而非只比shape，浮点容差按算法精度先定义再测，不能以宽容差掩盖错算；不支持的能力明确拒绝。
3. 在3D选输出格，逐项核对输入窗口、核翻转与乘加；调kernel/stride/padding，单步/播放暂停/局部计算与键盘动作一致。旋转/缩放/重置不改结果，3D呈现二维算子与真正三维数据轴标识不可混淆。演示值保持标记，不能进入课堂事实/老师原话。
4. 用户改参数/拖动/复制/删除/撤销、后台重整/新来源/五档切换交错，检查object_id/Fact IDs/SourceEdges、删除意图与局部patch。来源移除/彻底删除分别验，保留手动副本资源可用，失效来源不再显示原文。
5. 拆出/放回/关窗/重启/干净库包恢复后核查参数、选中格、必要视角、步骤与暂停状态；未知模板/旧包升级必须明确降级、不能标交互通过。PDF/Markdown包含静态化说明及同一参数下的可读数据/公式/来源。
6. 真macOS WKWebView打开课程窗/六格及拆出窗；录音/实时ASR/focaus同时运行。观察CPU/内存/GPU/帧与原声落盘，离屏停止调度、资源释放可重建、context lost注入恢复、渲染失败保笔记可读。测键盘/屏幕阅读器替代、reduced motion。记录容量曲线，再共同确定尚未定资源/性能门槛；不能降低可靠录音或15秒要求。

### 9.2 V22–V24：全文搜索

建立可人工穷举命中的测试集：中英混合/大小写/组合音标/emoji代理对/Unicode casefold扩展/空白折叠，重复字符串分属不同原页、同内容原页与重构对象，跨文本runs及不应跨cell的短词；标题/表格/图表标签/结构图/组件说明/公式规范文本；长转写中未挂载尾部、未挂载课件页、部分OCR/失败区域。固定预期命中集合、原文标量范围和页/region/object/time。

1. 在每类scope执行query/page/locate，核对全集/计数/上一处下一处/清空/无结果，原始和二次单独全覆盖；使用不出现的词验证partial覆盖不能写“确定无结果”。同一来源双视图一次计数，不同原位相同文字仍各计。
2. 验证NFC/casefold映射到原始字素、DOM UTF-16范围，组合字/emoji不能裂开；图形命中定位对象和说明，不假装文字像素精确高亮。未挂载页要真实挂载/滚动，不能只给一个hit JSON。
3. 在两个课程窗、拆出窗/编辑器/工具栏间切焦点，Command+F只路由一个正确view；IME选词的Enter/Escape不跳转/关闭，自有搜索与WebView默认查找不双开。清空不删正文，Escape恢复焦点不回滚编辑。
4. 人为延迟旧query、实时追加transcript、重整笔记/用户编辑、切实际语言档、重解析课件。旧query_seq不能覆盖，分页不混generation，选中仍有效则不抢滚动；失效时提示而不高亮同offset新词。索引尚未完成有范围和临时计数。
5. current/historical分别验detach、永久删除、整次录音归属转移；在query返回后删除、locate前删除、分页中删、窗口断连/休眠、重建中删、恢复旧包等竞态下，已删原文不得通过索引/缓存重现。保留副本在自身scope可搜，历史允许读与墓碑禁读区分。
6. 测索引体积/增量等待/查询耗时/内存/重建成本与录音竞争，先给基线再锁未定门槛。正确性用人工全集及稳定锚点，不用AI检索结果作真值；若换FTS加速必须复跑中文短词与全部Unicode样例。

### 9.3 V25/V26：focaus理解衔接

从已人工对齐的真实L8/L9范围选择长漏听、连续推导中途、例子/应用、主题切换、缺录/ASR迟到/未匹配场景，允许同文件多场景/一场景多文件。人工先标“触发时老师要解决的问题”“此刻步骤”“可证明的讲授推进关系”“继续听懂的最小前提及局部符号”“哪些信息缺证据”。原声为主、课件核写法，旧转写/模型生成笔记不是唯一真值。

在1倍速回放固定触发点，仅给当时可得证据；按不同漏听窗口/用户起点触发，记录完整结果、输入快照/范围/检索定义/路径节点及双截止。评审检查是否解释当前问题、衔接成立且未编教师动机、关键前提充分、示例/主题场景确有取舍、简短无多余内容、缺录与系统解释诚实。更早定义可补，局部重定义必须命中当前有效版本，不能用更晚课堂答案泄漏。

理解效果用真实学习者/人工评审的具体任务验证：读focaus后用自己的话说明当前问题、此前结论如何接入、当前符号与必要条件，并继续听预先指定的后续片段回答依赖当前上下文的问题。标准答案由原声和专家校对形成，记录错误/缺失/不确定、阅读负担与继续听的困难。与同模型/同可得输入的普通摘要做配对对照，轮换顺序减少熟悉效应；不是要求固定四段输出，也不假设用户统一知识水平。先报告基线与失败样例，再共同锁定尚未确定的效果门槛，不捏造通过率。

V26逐次测UI输入→检索→模型→来源/完整性校验→全部必要内容可见，完整≤15秒；旧历史概述先出、较晚补桥接不通过。注入延迟/限流/长上下文/早定义检索/转换与组件竞争；partial/unknown必要证据/超时单列，不从分母删除。生成后推进全局指针，确认body hash/截止不动、指针截止独立、>30秒陈旧仍从音频算；手校准、不同请求代次、拆出计时移交、转移/删源均拒迟到覆盖。V06/V07原固定要求继续有效，V25/V26只是补充分辨理解与时效，不降门槛。
